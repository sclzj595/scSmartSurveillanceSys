智能视觉平台 · 产品需求文档 v2.1

v2.1（取代 v2.0 / v1.0） 2026-10-17 状态：评审中 前序：v1.0 单机闭环版

v1.0 定义了单机安防闭环并落地了异步识别管线。v2.0 将视野升级为以机器视觉为核心的智能视觉平台：把"视觉引擎共性能力"与"安防业务规则"分离，使后续接入 RTSP、移动端、运动相机、门锁时不需要推翻重做。单机安防闭环降级为平台上的第一个业务应用。

阅读指引：第 4 章是本文档的锚点——模块边界一旦确定，各章需求都挂在边界内。✅ = 已落地（含代码），◐ = 部分完成，⬜ = 未开始。

1 产品定位、愿景与演进路线

1.1 定位

以机器视觉为核心的智能视觉平台：统一的视频接入、低延迟帧调度、识别引擎、事件系统，向上支撑多个业务应用（安防监控是第一个），向下适配多种视频源与硬件（USB / RTSP / 运动相机 / 门锁），并向多端（桌面、移动）开放同一套业务能力。

1.2 愿景与演进路线

阶段形态关键能力状态
S1 桌面单机Qt 桌面应用USB 源 + 视觉引擎 + 安防业务闭环 + 事件系统◐ 进行中
S1.5 设备抽象同上源抽象层落地，RTSP 接入，为多源多端铺路⬜
S2 多端协同桌面 + 移动端事件/状态实时推送（WebSocket），移动端查看与控制，远程视频链路评估⬜
S3 硬件生态平台 + 硬件插件运动相机 SDK 接入；授权门锁的人脸识别开锁联动⬜

1.3 架构总原则

  • 桌面客户端是当前的主要操作端，但不成为识别能力的唯一载体——引擎与业务运行在桌面进程内的分层模块中，接口按"可拆出为独立服务"的边界设计，未来拆分时客户端零重写。
  • 采集、视觉分析、事件管理、设备控制四域有清晰边界（第 4 章），新增手机端与硬件时只在边界处扩展。
  • 传输通道按数据类型选择，不默认用 WebSocket 传视频（第 5.3 矩阵）。
  • 移动端 = 共享业务状态与控制能力，不是把 Qt 界面搬上手机（第 9 章）。

2.2 已具备的技术资产

  • 异步识别管线：采集线程 → FrameBank → 分析线程（25Hz 自适应跳帧）→ GUI 渲染节拍（30fps）。GUI 线程零 CV 计算。
  • 结构化结果通道：AnalysisResult（人脸/遗留物/入侵）跨线程传递，检测与渲染解耦。
  • 诊断角标：预览 fps / 分析 Hz / 单帧耗时 / 帧龄四项实时显示（5.2 指标体系的基础）。
  • 网格直方图 LBPH：4×4 网格 × 256 维归一化直方图描述子，距离值域可控、阈值可标定（6.1）。
  • 两段式异步注册：检测 → 弹窗预览/编辑姓名 → 入库，全程线程池执行，GUI 不冻结（6.3）。
  • 异常隔离：分析线程单帧异常仅丢帧记日志，算法缺陷不杀死进程（6.4）。
  • 构建防呆：CMake 默认 Release（历史教训：MinGW 留空 = -O0，CV 像素循环慢 3–5 倍）。
  • 算法基线：HAAR 人脸检测、LBPH 识别、MOG2 背景建模、禁区判定。

4.2 模块边界规则（不可违背）

边界规则违反的后果
引擎 ↔ 业务引擎只产出结构化结果（帧龄、目标、相似度），不感知"禁区/遗留物"等安防概念；规则判定在业务层换一个视觉应用（如运动相机场景）就要改引擎
业务 ↔ 客户端客户端只经统一业务接口读写事件/档案/规则/设备状态，不直接触达引擎内部与存储格式移动端接入时桌面逻辑重复开发
源 ↔ 引擎引擎经统一源接口取流，对 USB/RTSP/SDK 源类型无感知（FR-11）每加一种硬件就复制一条管线
渲染 ↔ 分析检测线程不绘制；标注由渲染端按结构化结果绘制（已落地）识别重载拖垮帧率（D2 复发）

5.1 管线模型（已落地）

[采集线程] --store(覆盖)--> [FrameBank 最新帧槽] --waitForNew--> [分析线程 ≤25Hz 自适应跳帧]
                                  │                                │ 结构化 AnalysisResult
                                  │ QTimer 33ms load()             ▼（队列信号）
                                  └────────> [GUI 渲染节拍 30fps] 缓存最新结果

背压语义：延迟上界 = 单帧处理耗时，不随运行时间累积（D1 根治）

6 机器视觉算法与识别结果规范

6.1 算法基线与演进

能力当前算法演进方向（不约束本期）
人脸检测HAAR 级联YOLO/MediaPipe 类检测器（引擎接口不变，可替换）

运动目标MOG2 背景建模光流/检测器级联跟踪

6.2 结构化结果规范（已落地，引擎出口契约）

AnalysisResult {
  faces[]     : { rect, name, similarity(0~100|-1), known }   // R1 口径
  objects[]   : { rect, durationMs, confirmedLeft }            // 遗留物
  intrusion   : { active, offenders[] }                        // 禁区（业务判定，引擎外）
  processMs / analysisFps                                      // 诊断
}
  • 相似度口径 R1：对外一律 0–100%（越高越相似），无结果显示"—"，内部数值/异常值永不渲染。
  • 标注规范 FR-08：绿=已识别、黄=陌生人（附相似度%，供阈值现场标定）、灰细=跟踪中、琥珀=遗留物、红虚线=禁区、红粗=入侵；中文经 QPainter 渲染。
  • 识别频率约束：≥ 10 次/秒（当前上限 25Hz 节流 + 跳帧）。
  • 相似度映射（09d36df 定版）：距离 d → 相似度 100 − 30d，值域 0–100%。调整映射或阈值须同步本条并附标定数据（Q9）。

6.3 人脸注册交互规范（两段式异步，已落地）

[点击注册] → 线程池：检测+提取最大人脸 ──失败──> 日志提示原因（无人脸/过小），按钮恢复
                │ 成功
                ▼
        弹窗：人脸灰度预览 + 姓名编辑框（建议名"用户N"自动跳过已占用）[注册|取消]
                │ 确认
                ▼
        线程池：入库训练 → 日志"人脸注册成功: {姓名}"
  • 两段均经 QtConcurrent + QFutureWatcher 执行，GUI 全程不冻结；执行中按钮置灰，取消/失败均恢复。
  • 准入口径与识别一致：最大人脸 ≥ 60×60px，否则拒绝注册（FaceTooSmall）。
  • 同名注册 = 补充样本：同一人多角度/多光照多次注册提高识别率，不新建档案。
  • 提取的人脸为私有副本（clone），弹窗/入库期间不受后续帧影响。

6.4 识别工程纪律（D10–D12 事故复盘转化的硬规则）

规则内容事故来源
分类器互斥同一 CascadeClassifier 禁止并发 detectMultiScale；检测/注册一律经 _mutex 串行，锁纪律由类型保证（检测方法不对外暴露）D10
GUI 零阻塞预计 >50ms 的工作不得进入 GUI 线程；统一 QtConcurrent + watcher 回 GUI 报结果D10
描述子同口径train 与 predict 必须经同一 describe() 路径，库存描述子不存原始图；predict 对尺寸不符样本防御跳过D11
单帧异常隔离分析线程 try/catch（cv::Exception + std::exception）：单帧异常仅丢帧记日志，算法缺陷不杀死进程D11
度量先验证引入新比对度量时先确认值域与阈值语义可标定（距离→相似度映射有依据），不允许"值域未知先定阈值"D12
Release 防呆CMake 默认 Release；性能改动附 -O3 前后测量（-O0 下 CV 慢 3–5 倍，禁止据 -O0 数据做决策）构建排查

7 设备管理与硬件接入规范

7.1 统一源接口（FR-11，S1.5 核心）

启停控制打开/关闭/暂停✅⬜⬜⬜ 控制类

门锁是控制型设备而非视频源：只提供"开锁指令 + 状态回报"，人脸识别仍由视频源侧引擎完成，识别通过 → 业务层审计授权 → 下发开锁 → 产生"开门事件+抓拍存证"。门锁型号与通信协议 [TBD：Q3]。

7.2 视频源连接状态机（继承 v1 4.2，V0.6 落地 D9）

未连接 → 连接中（3s 超时回退）→ 在线 →（拔出/断流）重连中（指数退避 1s→30s 上限，恢复后从最新帧继续）→ 连续 5 次失败回到未连接并产生"源离线"事件。恢复后不回放中断帧。

7.3 RTSP 接入要求（FR-12，S1.5）

  • 添加方式：URL + 可选凭据；凭据不入 Git（第 10 章）。ONVIF 自动发现 [TBD：Q2]。
  • 网络抖动积压时执行与 5.1 相同的丢帧保最新策略；断流重连按 7.2 状态机。
  • 本期单路 RTSP 稳定优先；多路并发 [TBD]。
