## 1. 项目定位

以**机器视觉为核心**的智能视觉平台：统一视频接入 → 低延迟帧调度 → 可插拔识别引擎 → 结构化事件系统。**安防监控是第一个业务应用**，后续扩展 RTSP、移动端协同、运动相机、门锁联动。

| 项 | 内容 |
|---|---|
| 技术栈 | C++17 / Qt 5.15.2（MinGW 8.1）/ OpenCV 4.5.2 / CMake / QtConcurrent |
| 构建 | MinGW Makefiles · Release（Debug 下 -O0 会慢 3–5 倍，直接导致识别卡顿） |
| 姊妹项目 | FaceGate 人脸闸机（复用同一算法库）、FaceAlgorithm 算法 DLL、MediaLink 服务层 |

## 2. 四仓库布局（MachineVision-Suite/）

```
MachineVision-Suite/
├── FaceAlgorithm/    # 算法 DLL：纯 OpenCV+STL 业务无关人脸识别（detectAndRecognize）
├── MediaLink/        # 服务层：HTTP 只读 API + FFmpeg 管道推流（纯 STL，无 Qt 依赖）
├── FaceGate/         # 姊妹项目：人脸闸机门禁（同套 FrameBank/ActiveObject 管线）
└── SmartSurveillance/ # 本项目：智能安防监控
```

一套算法（FaceAlgorithm.dll）支撑**人脸闸机门禁 + 智能安防监控**双项目复用；WebRTC 推流与 HTTP 接口由独立服务层 MediaLink 两项目共用。

## 4. 核心架构成果

### 4.1 异步识别管线（FR-01，修 D1/D2 的根基）

```
[采集线程] --store(覆盖式)--> [FrameBank 最新帧槽] --waitForNew--> [分析线程 25Hz 自适应跳帧]
                                                                      | 队列信号(AnalysisResult)
[GUI线程]  QTimer 30fps --load--> FrameBank --clone--> QPainter叠加标注 <-- onAnalysisReady
```

- **覆盖式单槽**（FrameBank）：天然背压，GUI 消费慢不会堆积事件——从根上消除延迟累积（D1）
- **三线程解耦**：GUI 线程零 CV 计算，只做轻量绘制与缩放；延迟上界 = 单帧处理耗时（D2）
- **实测指标**：帧龄 9ms（目标 250ms）、分析耗时 ~88ms、预览 22fps、延迟无累积

### 4.2 数据/呈现分离

引擎只产出结构化 `AnalysisResult`（人脸框/label/相似度/目标/禁区判定），标注统一由 `OverlayRenderer` 绘制（QPainter 中文渲染，FR-08 诊断角标）。

### 4.3 事件中心（V0.4，PRD 第 8 章）

- 业务判定留在 GUI 侧（"什么算事件"是业务规则）：R2 冷却表（同人 30s / 陌生人 30s / 禁区 10s / 遗留物 60s 防抖）
- 渲染节拍**搭车截图**：本帧标注图恰好为全分辨率存证所需
- 独立 worker 线程异步落盘（events.jsonl + 按日期目录 jpg），磁盘失败仅提示不阻塞识别（R4）

### 4.4 统一视频源抽象（V0.6，PRD 5.2 设备层）

```
VideoSourceConfig ──> createVideoSource() 工厂
                        ├── UsbCameraSource   (cv::CAP_DSHOW)
                        └── RtspSource        (cv::CAP_FFMPEG, TCP + stimeout 有界 I/O)
                      IVideoSource: open() / read() / close() / describe()
```

- 源只做**单次 open/read/close，自身无重连状态**；断流检测与退避重连统一由采集线程编排
- RTSP：强制 over-TCP（防 UDP 花屏）+ FFmpeg `stimeout` 3s（本份 OpenCV 4.5.2 无 `CAP_PROP_OPEN/READ_TIMEOUT_MSEC`，经 `OPENCV_FFMPEG_CAPTURE_OPTIONS` 注入），断网时 read 有界返回不挂线程
- 源切换对话框（USB0/USB1/RTSP URL）+ sys_param.ini 持久化恢复；RTSP open 移入工作线程不阻塞 GUI
- 后续 ONVIF / 移动相机 / 文件回放源即插即得一致的恢复能力

### 4.5 独立服务层 MediaLink（V0.7 先行部分，PRD 第 9 章）

- HTTP 只读 API（`/api/health` `/api/events` `/api/persons` `/api/stream`，CORS，:8080）
- FFmpeg 管道推流（→ MediaMTX → WHEP/HLS），Degraded 状态不阻塞宿主
- 数据注入经 Provider 回调：业务留在宿主（EventStore/FaceRecognition），服务层不持有业务状态
- 日志回调经 QueuedConnection 切回 GUI 线程，杜绝跨线程碰 UI
- nlohmann/json + cpp-httplib 单头依赖

### 4.6 两段式异步人脸注册

检测（QtConcurrent 异步）→ 弹窗预览/编辑姓名 → 入库训练（异步）→ 结果回显；同名 = 补充样本；GUI 全程不冻结（配合 D10 分类器锁纪律）。

## 5. 缺陷修复全记录（D1–D12）

| # | 缺陷 | 根因 | 修复 |
|---|---|---|---|
| D1 | 延迟累积 | 队列信号无背压，消费慢→事件堆积 | FrameBank 覆盖式单槽（V0.2） |
| D2 | 卡顿 14–30fps | GUI 线程跑 CV 计算 + Debug -O0 构建 | 三线程解耦 + Release 构建（V0.2/V0.3） |
| D5 | 禁区坐标错位 | 双层根因：widget→label 坐标未映射 + 未按 KeepAspectRatio 反缩放 | `cfd5d23` 坐标链统一到源帧空间（V0.5） |
| D6 | 人脸档案重启丢失 | 无持久化 | FaceAlgorithm 模型存取（YAML）+ label→姓名 JSON（V0.5） |
| D7 | 事件不留痕 | 无持久化 | events.jsonl + 截图存证 + 历史查询（V0.4） |
| D9 | 设备断流不恢复 | 无重连编排 | V0.6：close→指数退避 500ms→8s→重开，USB/RTSP 统一路径（`2ef01ae`） |
| D10 | 点注册卡死崩溃 | 并发 detectMultiScale + GUI 阻塞 | 分类器锁纪律 + 注册全程异步（`0b044c3`） |
| D11 | 开识别崩溃 | train/predict 特征口径不一致 | 描述子同口径 + 单帧异常隔离（`2e733e0`） |
| D12 | 注册后仍判陌生人 | 逐像素 L2 度量缺陷 | 网格直方图 LBPH（4×4 格 × 256 维）（`09d36df`） |
