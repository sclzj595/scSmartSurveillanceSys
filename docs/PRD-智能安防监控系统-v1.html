智能安防监控系统 · 产品需求文档

版本 v1.0 2026-10-17 状态：评审中 P0 = Phase 1 本期 P1 = Phase 2 P2 = Phase 3 方向

定位：准商用单机桌面软件。基于现场摄像头的实时识别与告警工具，面向店铺、工作室、家庭门口等小微场景的现场操作员。本期以单路 USB 摄像头完成核心闭环，随后按 网络摄像头 RTSP → 门锁联动 / 运动相机 SDK 的顺序扩展硬件接入。

1 背景与目标

1.1 背景与证据

项目已有一个可运行的原型（Qt + OpenCV，课程迭代成果），具备人脸检测识别、遗留物检测、禁区入侵检测三个能力骨架。但实际运行暴露出一组体验与可靠性问题，使其还不能作为日常工具使用：

编号观察到的现象对用户的影响严重度
D1开启识别功能后，画面显示滞后于现场，且延迟随运行时间逐渐增大"实时"监控失去意义，事件响应慢P0
D2帧率在 14–30 fps 间波动，肉眼可见卡顿画面不平滑，长时间观看疲劳P0
D3识别置信度位置显示超长数字串（内部最大浮点值被直接渲染）不可读，观感差，暴露内部状态P0
D4画面上出现大量无意义的青色检测框（脸部、耳机、肩部均被框选）误报泛滥，用户不信任告警P0
D5手绘禁区与画面内容的实际位置不对应（窗口缩放/比例不一致时错位）入侵判定失准，漏报误报P0
D6注册的人脸档案重启后全部丢失（仅存在于内存）注册工作不可复用，核心能力形同虚设P0
D7事件只有一行滚动日志，无持久化记录、无截图存证事后无法追溯"什么时候发生了什么"——安防产品的底线P0
D8暂停后恢复，画面先回放暂停期间的旧帧操作困惑P1
D9摄像头拔出/占用时无处理（黑屏或崩溃风险）长时间无人值守运行不可靠P1

1.2 目标（可观察的结果）

  • 开启全部识别功能的情况下，预览依然实时、流畅、稳定，延迟与帧率不随运行时间劣化（量化指标见 FR-01）。
  • 注册一次人脸，重启后依然有效；识别结果以人话呈现（"张三 92%"，而非内部数值）。
  • 任何识别事件（人员识别、陌生人、遗留物、入侵）都会留下可查证的记录与截图。
  • 画面上只出现有含义的标注，用户看到的每一个框都对应一条真实规则。
  • 作为准商用软件的第一步：生物数据仅存本地、可知情、可删除。

3 范围与阶段

3.1 Phase 1（P0，本期）—— 单路闭环

  • 入口条件：一台 USB 摄像头 + Windows 桌面。
  • P0 动作：低延迟预览管线（FR-01）、源管理（FR-02）、人脸识别（FR-03）、人员档案（FR-04）、遗留物检测（FR-05）、禁区入侵（FR-06）、事件中心（FR-07）、标注规范（FR-08）、设置持久化（FR-09）、隐私合规（FR-10）。
  • 完成证据：24 小时无人值守运行后，事件记录完整可查，预览无劣化。

3.2 Phase 2（P1）—— 设备抽象与 RTSP

  • 设备抽象层（FR-11）：USB / RTSP / 文件回放统一接口，为运动相机、门锁预留插件位。
  • RTSP 网络摄像头接入（FR-12）：断流重连、网络抖动下"最新帧"策略。多路并发[TBD]，本期先保证单路 RTSP 稳定。

3.3 Phase 3（P2，方向）—— 硬件联动

  • 门锁人脸识别：识别通过 → 下发开锁指令 → 产生"开门事件"+ 抓拍存证。通信协议与门锁型号[TBD]。
  • 运动相机接入：通过厂商 SDK 取流（候选品牌[TBD]），复用 FR-11 插件机制，做便携/临时布防场景。

3.4 非目标（本期明确不做）

  • 云端存储、云端人脸库（合规与成本原因，生物数据不出本机）。
  • 移动端 App、远程 Web 查看。
  • 多用户账户体系与权限管理（单管理员即可完成 P0 旅程）。
  • 目标检测模型（YOLO 类）替换现有检测器——列为技术演进备选，不作为本期需求约束。

5 功能需求

FR-01实时视频预览管线P0

目的：操作员看到的画面与现场同步——这是安防软件的合格线，也是 D1/D2 的直接解法。产品要求：识别计算再重，也不允许拖慢预览。

处理规则
采集、识别、渲染三个环节解耦执行，互不阻塞。
丢帧策略（核心决策）：识别或渲染消费不及时时，丢弃旧帧、只处理/显示最新帧。宁可丢帧，不可累积延迟。
识别类处理允许降频运行（≥ 10 次/秒），预览渲染必须满帧。
量化指标（产品验收口径）
预览帧率 ≥ 24 fps（720p），识别全开时同样成立；波动 ≤ ±2 fps。
端到端延迟 ≤ 250 ms（标定方法：画面内秒表与系统时钟同框比对）。
连续运行 2 小时，延迟与内存不随时间增长。
异常
摄像头被其他程序占用：提示原因，每 3 秒自动重试，期间进入"未连接"空态。
启动时无摄像头：进入无源空态，识别类按钮置灰并给出引导文案。
FR-02视频源管理P0
触发
启动自动连接默认设备；设置中可切换可用设备（下拉枚举本机摄像头）。
处理规则
暂停 = 画面冻结 + 角落显著"已暂停"水印；恢复时丢弃暂停期间积压的所有帧，从最新帧继续（修复 D8）。
默认请求 1280×720@30fps；设备不支持时取其最接近档位[Assumption]。
退出软件自动释放设备，不占用摄像头。
状态
连接状态机见 4.2。
FR-03人脸检测与识别P0
触发
操作员开启"人脸识别"开关（默认关闭，记忆上次状态）。
处理规则
检测画面中人脸 → 与人员档案库比对 → 输出"档案名 + 相似度%"或"陌生人"。
相似度口径与阈值遵循 R1；默认阈值 60%[Assumption，可调 40–95]。
人脸过小（短边 < 60px）不参与识别，避免远处误报。
低照度画面自动增强对比度后再检测。
结果与状态
识别命中 → 绿框 + 档案名 + 相似度%，产生"人员识别"事件（受 R2 冷却约束）。
未命中 → 黄框 + "陌生人"，产生"陌生人"事件（受 R2 冷却约束）。
异常
档案库为空：全部标"陌生人"，事件同样受冷却约束，不产生告警风暴。
FR-04人员档案与人脸库管理P0
触发
点击"注册人脸"，从当前画面取最大的人脸。
处理规则
命名 → 质量校验（人脸过小/过暗拒绝并提示原因）→ 入库。
可向已有档案追加样本（同名即追加），提升识别稳定性。
首次注册弹出知情同意（见 FR-10），同意后方可继续。
结果与状态
档案持久化：重启软件后全部档案与样本完整可用（修复 D6）。
删除档案：二次确认，物理删除其全部样本与特征数据。
FR-05遗留物检测P0默认关闭
触发
操作员手动开启（背景建模类算法在普通桌面场景误报率高，故默认关闭[Assumption]）。
处理规则
静止物体持续存在超过阈值（默认 60s，可调）→ 产生"遗留物"事件。
遗留物被移走 → 产生"遗留物解除"事件。
标注纪律（修复 D4）：只有停留超过阈值、被确认为遗留物的目标才显示黄色告警框；仍在跟踪中的目标最多显示灰色细框，不喧宾夺主。
面积小于阈值的噪点不计入。
FR-06禁区入侵检测P0
触发
点击"设置禁区"进入绘制模式，在视频画面上拖拽矩形；再次点击退出；可一键清除。
处理规则
绘制坐标按 R3 映射到源帧坐标系（修复 D5）；窗口缩放/比例变化后判定依然准确。
目标（人脸或跟踪目标）进入禁区面积 ≥ 30% → 产生"入侵"事件，冷却期遵循 R2。
触发时红色标注 + 声音提示（声音默认开，可在设置关闭）。
结果与状态
禁区配置持久化，重启后恢复；画面常显红色虚线框。
FR-07事件与告警中心P0

目的：让"发生过什么"可追溯——安防产品从玩具变为工具的分界线（解法 D7）。

事件类型
人员识别 / 陌生人出现 / 遗留物 / 遗留物解除 / 禁区入侵 / 源离线。
处理规则
每个事件记录：类型、精确时间、标注后的截图存证（遵循 R4）、关联档案或目标描述。
界面呈现三通道：日志区滚动条目（现状保留）+ "事件中心"按钮角标未读数 + 可选声音。
事件中心：时间倒序列表 → 点击查看大图详情；支持按类型筛选。
持久化
事件与截图本地保存，重启可查；删除遵循 4.3 生命周期。
异常
磁盘写入失败：界面提示，识别功能不中断。
FR-08画面标注与渲染规范P0

目的：画面上的每一个框都有含义（解法 D3/D4）。规范全局唯一，见 4.4 线框图例：

含义样式文字
已识别人脸绿色实线框档案名 + 相似度%（如"张三 92%"）
陌生人黄色实线框"陌生人"
跟踪中目标灰色细线框（低调）无文字
遗留物（已确认）琥珀色实线框"遗留物 N分钟"
禁区红色虚线框"禁区"
入侵目标红色实线加粗框"入侵"
处理规则
置信度/相似度只以百分比呈现，内部数值（含异常值）永不渲染到画面（修复 D3）。
右上角常驻诊断小字：fps · 端到端延迟 · 源状态，可在设置中关闭。
FR-09系统设置与持久化P0
设置项默认值生效方式
主题（深/浅）深色即时生效，已持久化（现状保留）
摄像头设备系统默认切换后重连
相似度阈值60%即时生效
遗留物时长阈值60 秒即时生效
告警声音开即时生效
诊断信息显示开即时生效
事件截图存证开即时生效（关闭后事件仍记录，仅无截图）
FR-10敏感数据处理与隐私（准商用门槛）P0

人脸图像属于敏感生物特征信息，准商用定位下以下规则为硬性要求：

知情同意
首次注册人脸时弹窗告知：采集内容、存储位置（本机）、用途（仅本地识别）、删除方式；同意后方可入库。已注册用户不受影响。
本地化
人脸数据、事件记录、截图仅保存在本机，软件无任何网络上传行为（RTSP 拉流除外，且仅指向用户自己配置的设备）。
可删除
删除档案即物理删除其生物数据；设置中提供"一键清除全部生物数据"，二次确认后执行。
留存边界
事件截图默认保留[TBD：建议 30 天自动清理]；日志不记录人脸图像本体。
交付物
随软件提供简版隐私说明[TBD：是否需要独立文档与法务评审]。
FR-11设备抽象层（为硬件路线铺路）P1
目的
让"运动相机 / 门锁 / 网络摄像头"以插件方式接入，而非各自为政——这是三条硬件路线的共同地基。
处理规则
统一源接口：取流、启停、连接状态上报、能力描述（分辨率/帧率）；上层功能（识别、事件）对源类型无感知。
v1 内部先把 USB 源重构到该抽象之上（Phase 1 顺带完成），Phase 2 增加 RTSP 实现，Phase 3 增加门锁/运动相机实现。
FR-12RTSP 网络摄像头接入P1
触发
操作员添加网络摄像头（URL + 可选凭据）。
处理规则
断流自动重连（指数退避：1s/2s/4s/…/上限 30s）；重连成功产生"源恢复"记录。
网络抖动导致积压时，执行与 FR-01 相同的"丢旧帧保最新"策略。
本期单路 RTSP；多路并发与通道管理[TBD]。

6 共享规则（全局唯一口径）

编号规则定义
R1相似度口径对外统一为 0–100%，越高越相似。内部算法无论以何种距离/误差度量，一律转换后再呈现；异常或无结果时显示"—"，禁止渲染内部数值（修复 D3 的机制保障）。
R2事件冷却同类型 + 同目标的事件在冷却窗口内合并为一条：人员识别/陌生人 30s，入侵 10s，遗留物状态变化不冷却。冷却只合并事件，不抑制画面标注。
R3坐标映射显示坐标 ↔ 源帧坐标换算统一实现：等比缩放 + 居中留边（letterbox）偏移补偿。禁区绘制、标注绘制、点击交互全部经此规则，任何模块不得自行换算。
R4截图存证事件触发瞬间保存标注后的画面帧，按 事件目录/日期/时分秒_类型.png 命名；设置中可关闭（FR-09）。
R5权限v1 单管理员：操作员拥有全部操作权；数据主体的知情与删除权通过操作员执行（FR-10 承载）。无其他角色。
